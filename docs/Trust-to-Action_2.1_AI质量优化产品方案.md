# Trust-to-Action 2.1 AI 质量与企业试点体验方案

> 文档版本：2.1 AI Quality Pilot
> 更新日期：2026-08-24
> 维护状态：当前唯一产品基线
> 本地评审入口：`http://127.0.0.1:4174/`

## 1. 产品目标

Trust-to-Action 2.1 在保留 2.0 内容运营闭环的基础上，优先提升客户状态判断与下一最佳动作（NBA）的实际可用质量，并把本地 Dogfood 升级为具备服务端身份边界、持久化和版本治理的企业试点原型。

本版核心流程：

`客户与有效证据 → AI 评估候选 → 销售判断 → 确定性校验 → 客户状态/NBA 写入 → 7 天质量复查 → 反馈聚类 → Prompt/路由候选 → 黄金集评测 → 负责人发布或回滚`

### 1.1 North Star

“首稿有效采用率”定义为：48 小时内已审阅的候选中，销售原样采用，且 7 天内未因 AI 判断错误撤销或覆盖的比例。

- 分母：48 小时内完成审阅且已有 7 天质量复查结果的候选。
- 分子：销售原样采用，并被标记为 `retained` 或 `new_evidence` 的候选。
- `quality_reversal` 计为 AI 质量失败。
- 因新增证据导致的正常状态迁移不计失败。
- 修改后采用和拒绝进入分母但不进入分子。

目标：相较 2.0 锁定 Holdout 基线提升至少 15 个百分点，绝对值不低于 70%，审阅覆盖率不低于 80%。

### 1.2 非目标

- 不接真实企业微信、生产客户数据、会话存档 SDK、企微 SSO 或生产数据库。
- 不自动发布、私聊、回复客服、群发或发送 Offer。
- 不对其余六类 AI 输出做 2.1 级调优；周策略、内容草稿、风险分析、会话洞察、内容 Brief 和周复盘保持 2.0 行为。
- 不做微调、线上随机 A/B、三模型路由或业务因果归因。
- 不将完整提示词、API Key 或客户正文副本写入 SQLite、日志或前端状态。

## 2. 用户与权限

| 能力 | 运营 | 销售 | 负责人 |
|---|---:|---:|---:|
| 生成客户评估候选 | 是 | 仅本人/共享客户 | 是 |
| 审阅候选、原样采用、修改或拒绝 | 否 | 仅本人/共享客户 | 否 |
| 记录 7 天质量复查 | 否 | 仅本人判断 | 否 |
| 查看 AI 质量中心 | 全部质量数据 | 本人反馈与本人客户 | 全部质量数据 |
| 创建 Prompt/路由候选、运行评测 | 是 | 否 | 只读 |
| 发布或回滚 Prompt/路由 | 否 | 否 | 是 |
| 配置本地 OpenAI Key | 是 | 否 | 是 |
| 查看会话原文 | 否 | 仅本人会话且审计 | 全部且审计 |

权限由 BFF 签名会话决定。前端不再通过 `x-tta-role` 声明身份；销售的客户、候选、决策、任务、会话和审计记录在服务端投影后返回。运营收到的会话身份和正文为确定性脱敏版本。

## 3. 客户评估体验

### 3.1 生成候选

- 单客户评估通过 `POST /api/v2/ai/customer-evaluation` 显式触发。
- 批量评估每批 1-10 位客户，允许部分成功；某位客户失败不会丢弃其他成功结果。
- 请求包含幂等键，相同租户、操作和幂等键只保存并返回同一结果，避免重复调用和重复计费。
- 生成只保存 `GenerationRun` 与 `EvaluationCandidate`，不修改客户状态，不执行 NBA。

候选绑定：

- 客户 `revision`。
- 当前有效证据的时间、有效性和引用指纹。
- Prompt 版本、路由版本、模型、response ID、时延、token usage 和升级来源。
- 48 小时候选处理窗口。

客户或证据变化后，仍待处理的候选立即标记为过期。历史已采用、修改或拒绝的候选保留原快照，不被重新计为过期。

### 3.2 销售审阅

客户详情首屏同时展示当前状态、有效证据、建议状态、置信度、NBA、依据摘要、不建议动作、风险、未知项和模型路由。销售可以：

1. 原样采用：不要求原因，确定性门禁通过后写入客户状态与 NBA。
2. 修改后采用：必须选择原因并提供完整修改结果。
3. 拒绝：必须选择原因，不写入客户状态。

结构化原因固定为：状态错误、证据错误、NBA 不合适、缺少上下文、风险或合规、过于泛化、其他。选择“其他”时必须填写说明。请求失败、候选过期或发生 409 冲突时保留用户输入，并要求加载最新状态重新评估。

### 3.3 7 天复查

原样采用后的判断进入质量复查队列：

- `retained`：原判断保持有效。
- `quality_reversal`：因 AI 状态、证据或 NBA 判断错误撤销，计为质量失败。
- `new_evidence`：新事实推动正常变化，不计质量失败。

所有结果记录判断人、时间、原因和审计事件；不自动反转已写入的历史客户状态。

## 4. AI 质量中心 `/ai-quality`

质量中心展示：

- 首稿有效采用率、相对 2.0 基线提升和审阅覆盖率。
- 状态准确率、NBA 可接受率、证据引用精度、P95 时延。
- Terra 分流占比、主模型升级率、策略违规和隐私泄露。
- 修改/拒绝原因分布、失败聚类和最近运行。
- 200 条黄金集的调优集/Holdout 评测结果。
- Prompt 与路由版本状态、发布和回滚操作。

运营可在桌面端创建 Prompt 或路由候选，填写版本名称、策略摘要和 Terra 升级阈值。负责人只能发布通过锁定 Holdout 的候选；可回滚到曾发布过的归档版本。移动端保留候选审阅、复查和指标查看，Prompt 编辑、黄金集管理和版本对比提示使用桌面端。

## 5. 模型路由与输出契约

### 5.1 路由

- 主模型：`gpt-5.6`。
- 轻量模型：`gpt-5.6-terra`。
- 只有 T0/T1、无异常、无成交事实、无敏感商业事实、无强证据冲突的简单场景进入 Terra。
- 高级状态、异常、成交事实、价格/投诉/敏感信息或矛盾证据直接使用主模型。
- Terra 置信度低于 75、拒答、结构失败或策略失败时最多升级一次至主模型。
- 主模型失败后阻断，不向低能力模型降级。
- Terra 权限不可用时进入主模型单路模式，并在健康状态显示警告。

本策略遵循 OpenAI 官方“先达到准确率目标，再优化成本与时延”的模型选择原则：[Model selection](https://developers.openai.com/api/docs/guides/model-selection)。

### 5.2 客户评估输出

`CustomerEvaluation` 在原 2.0 契约上增加：

- `decision`: `recommend | insufficient_evidence`。
- `evidence_assessment`: 证据 ID、支持状态/NBA/两者/均不支持、权重和公开摘要。
- `uncertainties`: 缺失上下文和未知项。

模型只返回可核对的公开依据，不要求或保存隐藏推理过程。证据不足时必须保持当前状态并返回 `insufficient_evidence`。

### 5.3 确定性门禁

- 状态保持或最多前进一步。
- 弱信号不能独立推动 D1/A1。
- D1/A1 必须引用有效强证据。
- C1 必须引用明确成交事实。
- 未知、失效或撤权证据阻断写入。
- NBA 必须来自固定动作集合。
- AI 不执行任何外部动作。

## 6. 黄金集、盲测与发布门槛

原型内置 200 条纯合成黄金集：160 条调优集、40 条锁定 Holdout；覆盖全部状态、行业语境、强弱证据、矛盾信号、失效证据、隐私、成交事实和异常场景。40 条（20%）标记为双人复核。

Holdout 为 2.0 与 2.1 提供隐藏版本、随机顺序的销售盲测口径，并包含合成的 7 天后续事件。评测过程遵循先描述任务、提供代表性输入、按明确 criteria 评分并迭代的原则：[Working with evals](https://developers.openai.com/api/docs/guides/evals)。本地原型不调用 OpenAI Evals API。

自动 grader 检查：

- 状态精确匹配。
- NBA 是否属于允许集合。
- 证据引用是否完整、存在且有效。
- 置信区间、越级迁移和 C1 成交事实。
- 未知证据、策略违规和隐私泄露。

模型 grader 只诊断解释质量，不解除确定性门禁。发布必须同时满足：

| 指标 | 门槛 |
|---|---:|
| 首稿有效采用率 | ≥70% 且较 2.0 提升 ≥15pp |
| 状态准确率 | ≥85% |
| NBA 可接受率 | ≥80% |
| 证据引用精度 | 100% |
| 策略违规 / 隐私泄露 | 0 / 0 |
| 关键切片回归 | ≤2pp |
| P95 时延 | ≤30s |

## 7. 数据对象与接口

新增版本化对象：`GenerationRun`、`EvaluationCandidate`、`EvaluationDecision`、`PromptVersion`、`RouterVersion`、`GoldenCase`、`EvalRun` 和 `EvalScore`。

`AiMeta` 增加：`router_version`、`route_reason`、`attempts`、`latency_ms`、输入/输出 token、`escalated_from` 和 `input_fingerprint`。

主要接口：

| Method | Path | 作用 |
|---|---|---|
| POST | `/api/v2/ai/customer-evaluation` | 返回并保存单客户候选与运行记录 |
| POST | `/api/v2/ai/customer-evaluations/batch` | 最多 10 位，部分成功 |
| POST | `/api/v2/customers/:id/evaluation-decisions` | 原样采用、修改或拒绝 |
| POST | `/api/v2/evaluation-decisions/:id/review` | 记录 7 天复查 |
| GET | `/api/v2/ai-quality/metrics` | 按角色范围返回质量指标 |
| GET | `/api/v2/ai-quality/runs` | 运行与评测记录 |
| GET | `/api/v2/ai-quality/golden-cases` | 运营/负责人黄金集 |
| POST | `/api/v2/ai-quality/eval-runs` | 运行调优集或 Holdout |
| POST | `/api/v2/ai-quality/prompt-versions` | 创建 Prompt 候选 |
| POST | `/api/v2/ai-quality/router-versions` | 创建路由候选 |
| POST | `/api/v2/ai-quality/:kind-versions/:id/promote` | 负责人发布 |
| POST | `/api/v2/ai-quality/:kind-versions/:id/rollback` | 负责人回滚 |

所有写请求使用签名会话、CSRF Token、对象 revision 和 Repository revision。冲突不覆盖最新数据。

## 8. 企业试点架构

### 8.1 数据层

- 默认 `VITE_DATA_MODE=http`，前端只通过 BFF 访问数据。
- `better-sqlite3` 使用 WAL、迁移文件和事务保存租户状态及幂等记录。
- 空租户自动装载 fixture V5：24 位合成客户、200 条黄金集和 2.0/2.1 质量历史。
- `StateRepository` 隔离存储实现，后续可替换为中国区 PostgreSQL。
- Mock + `localStorage` 仅用于单元测试和离线演示，使用 V2.1 独立命名空间。

### 8.2 身份与安全

- BFF 签发 HttpOnly、SameSite=Strict 的 HMAC 签名演示会话。
- 非安全方法必须携带匹配当前会话的 CSRF Token。
- 非开发环境必须配置 `SESSION_SECRET`；开发环境使用启动期临时密钥并显示健康警告。
- 租户、角色和客户范围由服务端决定，伪造 cookie 或前端角色头不能提权。
- `OPENAI_API_KEY` 只保存在 BFF 环境变量或进程内存中；配置时分别检查主模型和 Terra 权限。
- API Key、完整客户片段和模型正文不进入 SQLite、审计或运行日志。

## 9. 异常状态

- AI 未配置、主模型无权限、Terra 无权限、429、超时、拒答、结构失败。
- 候选过期、候选已处理、客户 revision 冲突、证据指纹变化。
- 幂等键重复、批量部分失败、Repository revision 冲突。
- 会话缺失、签名无效、CSRF 失效、角色无权限和客户不在范围。
- Holdout 未通过、关键切片回归、发布版本冲突、回滚目标无效。

所有失败保留当前输入，返回稳定错误码和重试提示；主模型失败不会生成低能力降级结果。

## 10. 测试与试点验收

自动化测试覆盖：

- North Star、审阅覆盖和 7 天复查分类。
- 候选快照过期、结构化原因、状态门禁和 409 冲突。
- 简单/复杂路由、Terra 低置信升级、Terra 不可用和主模型阻断。
- SQLite 迁移、重启持久化、事务冲突、租户与幂等隔离。
- 签名 cookie、伪造签名、过期会话、CSRF 和服务端角色投影。
- BFF 单客户、批量部分成功、幂等和销售判断写入。
- Prompt/路由候选、Holdout 发布门禁和负责人回滚。
- 1440×900、1024×768、390×844 的候选审阅、质量中心和响应式布局。

真实模型测试仅在 `RUN_LIVE_OPENAI_TEST=1` 时运行一个 Terra 简单场景和一个主模型高风险场景，CI 默认禁用。

试点准入要求：North Star 与全部发布门槛通过，审阅覆盖率不低于 80%，自动外发、未经授权引用、策略违规和隐私泄露均为 0。合成数据只能验证流程、决策质量和系统边界，真实企业效果仍需下一阶段中国区数据面试点验证。
