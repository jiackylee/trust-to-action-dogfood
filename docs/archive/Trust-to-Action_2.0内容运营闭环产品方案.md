# Trust-to-Action 2.0 内容运营闭环产品方案

> 文档版本：2.0 Content Operations Loop
> 更新日期：2026-08-24
> 维护状态：已归档，由 2.1 AI 质量优化方案替代
> 本地评审入口：`http://127.0.0.1:4174/`

## 1. 产品目标

Trust-to-Action 2.0 面向内部运营、销售和负责人，把合成会话信号转化为有证据、可审批、可人工发布并能回填结果的内容运营闭环：

`合成会话存档 → 脱敏洞察 → 内容 Brief → 草稿与证明 → 审批 → 人工发布 → 效果回填 → 下周策略`

主要用户为运营。销售确认本人会话洞察并回填咨询、Demo、Offer 和客户状态迁移；负责人处理敏感审批和原文访问治理。

北极星指标是“有效会话信号到朋友圈就绪草稿的中位时间”，两周场景评测门槛不超过 15 分钟。

### 1.1 非目标

- 不接真实会话内容存档 SDK、企业微信接口、生产身份认证或生产数据库。
- 不分析图片、语音、视频或文件正文，不做 OCR、ASR 或媒体理解。
- 不自动发布朋友圈、私聊、群发、回复客服或发送 Offer。
- 不把时间关联解释为业务因果，不用点赞或评论独立推动 D1/A1。
- 不把会话原文自动转为客户证明。

## 2. 用户与权限

| 能力 | 运营 | 销售 | 负责人 |
|---|---:|---:|---:|
| 查看内容经营台、洞察聚类和脱敏引用 | 是 | 是 | 是 |
| 接受、编辑或忽略洞察 | 是 | 否 | 否 |
| 生成并采用 Brief、编辑草稿、标记人工发布 | 是 | 否 | 否 |
| 查看会话原文 | 否 | 仅本人会话 | 全部，按需 |
| 回填平台互动 | 是，合成同步 | 否 | 只读 |
| 回填咨询、Demo、Offer、状态迁移 | 否 | 是 | 只读 |
| 处理客户证明、价格、承诺、投诉和敏感信息审批 | 否 | 否 | 是 |

每次原文展开必须先选择用途，记录会话、访问人、时间和用途。前端权限只用于原型体验，未来 HTTP 数据面必须再次鉴权。

## 3. 信息架构

### 3.1 内容经营台

运营首页优先展示：待判断洞察、已接受但缺 Brief、证明缺口、待审批、待人工发布、待回填结果和本周高表现主题。前三个阻塞点可在最多两次操作内进入目标对象。

北极星指标和内容就绪度位于首屏；销售和负责人继续使用角色专属销售任务与审批首页。

### 3.2 会话洞察池 `/insights`

支持按主题、洞察状态、信号类型、趋势范围和证据强度筛选。每条洞察展示：

- 问题、异议、期望结果或购买信号。
- 目标分组、脱敏引用、独立会话数、消息血缘、置信度和证据强度。
- 候选、已接受或已忽略状态及人工判断原因。
- 少于 3 个独立有效会话时固定标记“个体信号”，禁止称为趋势。

运营接受、编辑或忽略候选；编辑或忽略必须填写原因。只有已接受且血缘有效的洞察可以生成和采用内容 Brief。

### 3.3 内容 Brief

Brief 固定以下字段：目标客户、T/I/D/A 阶段、朋友圈主角度、关键事实、证明需求、唯一 CTA、截止时间和洞察引用。AI 只生成候选，运营人工采用后才能进入草稿。

朋友圈为主稿；销售话术和官网稿是同一 `content_family` 的派生版本。每个版本独立绑定渠道授权、确定性风险和审批。

### 3.4 草稿、证明与审批

桌面端保留草稿列表、正文编辑、证据/风险侧栏；显示 Brief 和已接受洞察血缘。自动保存、版本冲突、失败保留输入和未保存提示沿用现有能力。

客户原话、案例、量化结论、投诉、价格和敏感信息必须先成为经过脱敏、授权和负责人审批的证明资产。会话同意、消息有效性或证明授权撤销后，下游引用立即失效并阻断复制与发布标记。

### 3.5 发布与结果

复制草稿后，运营在确认真实人工操作已完成时标记发布。系统建立 7 天关联窗口，不调用任何企业微信发送接口。

结果分层展示：

| 层级 | 字段 | 性质 |
|---|---|---|
| 平台互动 | 可见客户、点赞、评论 | 确定性合成数据；点赞和评论为弱信号 |
| 业务结果 | 咨询、Demo、Offer、状态迁移 | 销售人工回填的业务事实 |

所有结果页面固定标记“时间关联，不代表因果”。

### 3.6 周复盘

按主题展示洞察采纳率、Brief 采用率、证明覆盖、审批耗时、互动同步率和业务回填率；将平台互动和业务结果分别汇总，形成下周策略候选。AI 周策略输入包含已接受洞察和历史内容结果。

## 4. 会话存档与治理模拟

原型包含 4 周确定性合成历史：36 个会话、252 条消息、12 个洞察、8 个 Brief、8 个历史发布记录和 6 个业务结果。

覆盖单聊、群聊、同意、拒绝、撤回、重复 `msgid`、`seq` 缺口、部分解密失败和超出 5 天补拉窗口。同步器固定模拟：

- 通过 `seq` 增量同步，单批最多 1000 条。
- 最近 5 天允许补拉；超窗记录保留治理元数据但不进入分析。
- SDK 解密失败、重复消息和撤回消息不进入模型输入。
- 同意拒绝或撤销后，相关消息与下游洞察不可继续使用。
- 文本与链接描述可进入分析；图片、语音、视频和文件只保留类型、文件名等元数据。

## 5. 数据对象与版本

新增对象：`ArchiveConsent`、`ArchiveConversation`、`ArchivedMessage`、`ConversationInsight`、`ContentBrief`、`ContentFamily`、`PublicationRecord`、`ContentOutcome` 和 `AnalysisBatch`。

`Draft` 增加 `brief_id`、`content_family_id` 和 `variant_of`。所有可变对象继续满足：

```ts
type Versioned<T> = T & {
  id: string;
  revision: number;
  updated_at: string;
};
```

写入必须携带 `expectedRevision`。冲突统一返回 `409 VERSION_CONFLICT` 和最新对象，界面保留本地输入。

`DataClient` 新增洞察批次、洞察决策、Brief、原文访问审计、人工发布、朋友圈结果同步、业务结果和周复盘方法。默认数据继续写入浏览器 `localStorage` 的 V2 合成数据命名空间。

## 6. 隐私与血缘政策

模型调用前必须按以下顺序处理：

1. 检查会话存档同意为 `agreed`。
2. 排除撤回、重复、解密失败、超出 5 天窗口和无权限消息。
3. 排除仅含媒体元数据、没有文本或链接描述的消息。
4. 对手机号、邮箱、微信号和证件号执行确定性脱敏。
5. 只发送消息 ID、会话 ID、合成客户 ID、消息类型、脱敏文本和时间。

模型输出的消息、会话或洞察引用必须全部存在于允许集合；未知引用返回策略错误并阻断保存。运营界面永不渲染原始消息和发送人个人信息。

## 7. AI 接口

本地 BFF 使用 OpenAI Responses API、Zod Structured Outputs，默认模型 `gpt-5.6`，不提供 Mock AI 降级。

| Method | Path | 主要输入 | 结构化输出 |
|---|---|---|---|
| POST | `/api/v2/ai/conversation-insights` | 存档消息、同意记录 | `ConversationInsights` |
| POST | `/api/v2/ai/content-brief` | 已接受洞察、历史业务结果 | `ContentBriefProposal` |
| POST | `/api/v2/ai/weekly-retrospective` | 洞察、Brief、发布与结果 | `WeeklyRetrospective` |
| POST | `/api/v2/ai/weekly-strategy` | 当前计划、已接受洞察、历史结果 | `WeeklyStrategy` |
| POST | `/api/v2/ai/content-draft` | 策略、Brief、洞察、证明与历史结果 | `ContentDraftProposal` |

响应继续包含模型、OpenAI response ID、提示词版本和生成时间。缺少 Key、超时、429、拒绝、结构错误、未知引用或隐私策略阻断均保留输入并返回明确错误；密钥不进入前端状态、日志或持久化。

## 8. 确定性门禁

- 单次点赞或评论不能独立支持 D1/A1。
- 客户状态最多前进一步；D1/A1 必须引用有效强证据；C1 必须有成交事实。
- 会话内容不是证明资产，模型风险建议不能解除审批门禁。
- 客户证明、价格/Offer、量化承诺、投诉和个人敏感信息必须由负责人审批。
- 同意、消息或授权撤销后，相关草稿不可复制、审批或标记发布。
- AI 永不自动发布、私聊、回复客服或发送 Offer。

## 9. 响应式与可访问性

- 1440×900：内容经营台首屏可见主题、北极星指标、六项队列和前三个阻塞点。
- 1024×768：64px 图标导航保留 `title` Tooltip、`aria-label` 和可见焦点。
- 390×844：洞察判断、审批、发布标记和结果回填可操作；长 Brief 和正文编辑提示使用桌面端。
- 表格在移动端替换为卡片，页面不产生横向滚动；对话框管理初始焦点、Tab 循环、Escape 和焦点恢复。

## 10. 测试与验收

自动化测试覆盖：同意门禁、撤回、重复、解密失败、5 天窗口、原文权限和审计、趋势阈值、洞察/Brief 血缘、证明授权、版本冲突、弱互动规则、人工发布和结果分层。

BFF 合约覆盖成功、429、隐私阻断、未知消息引用、未接受洞察和结构化复盘。真实 OpenAI 冒烟继续由 `RUN_LIVE_OPENAI_TEST=1` 显式启用。

两周场景评测门槛：

- 100% AI 洞察只引用已同意、有效且带时间的消息。
- 运营界面原始消息和个人敏感信息泄露为 0。
- 至少 60% 洞察候选被运营接受。
- 至少 90% 就绪草稿具有洞察血缘，敏感事实具有有效证明。
- 有效洞察到朋友圈就绪草稿中位时间不超过 15 分钟。
- 80% 已发布内容完成互动和业务结果回填。
- 自动外发、未经授权引用和弱信号独立推动 D1/A1 均为 0。

合成数据只能验证流程、权限、血缘和决策质量。真实内容增长效果是接入真实中国区数据面前的下一阶段准入条件。
